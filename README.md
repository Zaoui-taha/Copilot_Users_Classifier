# Copilot User Classifier

## Overview

This Data Science project focuses on **multi-class user identification from raw software interaction logs** generated by *Copilote*, a software solution developed by Infologic for the agri-food industry.

Each user session contains a browser identifier followed by a sequence of interaction events. The objective is to learn a behavioral signature for each user and predict the user identity (`util`) from previously unseen sessions.

The project follows a complete machine-learning workflow: **data exploration, feature engineering, model comparison, validation, interpretation, and final prediction generation**.

---

## Problem Statement

Software interaction logs are high-dimensional, irregular, and sequential. The main challenge is therefore not only to select a classifier, but to design a representation that captures meaningful behavioral differences between users.

The dataset contains:

- a user identifier (`util`) used as the target in the training set,
- the browser used during the session,
- a variable-length sequence of raw user actions,
- temporal markers of the form `tXX`, representing 5-second intervals.

The task is a **247-class classification problem** with a significant class imbalance.

---

## Methodology

### 1. Data Loading and Exploration

The dataset used in this project was provided as part of an academic Kaggle competition organized at École Centrale de Lyon.

The original competition files are not included in this repository:

```text
train.csv
test.csv
sample_submission.csv
```

Redistribution permission for these files has not yet been confirmed. The repository therefore currently contains only the project code, documentation, and report.

The raw files contain sessions with different numbers of actions. A line-by-line parsing strategy is used because the input format is irregular and produces a very large sparse representation when loaded directly as a conventional table.

Exploratory analysis focuses on:

- browser distribution,
- number of sessions per user,
- session duration,
- class imbalance,
- atypical but valid user behaviors.

Rare or unusually long sessions are retained because they may contain useful behavioral information and improve generalization.

---

## 2. Feature Engineering

Feature engineering is the core of the project. Two complementary types of variables are created.

### Static Features

These describe global session behavior:

- browser,
- total session duration,
- total number of actions,
- frequency of each generic action,
- most frequently used screens, configurations, and categories.

More than 7,000 raw actions are normalized and grouped into **35 generic action types**.

### Sequential Features

These capture how actions are ordered:

- first operation,
- last operation,
- action transitions,
- bigrams representing pairs of consecutive actions.

`TfidfVectorizer` is used to convert action sequences into a numerical representation.

---

## 3. First Modeling Iteration

Several supervised-learning models are evaluated:

| Model | Macro F1-score |
|---|---:|
| Random Forest, 300 trees | 0.7458 |
| Random Forest, 100 trees | 0.7298 |
| Logistic Regression | 0.5820 |
| MLP Classifier | ~0.51 |
| Linear SVC | 0.3683 |
| RBF SVC | 0.1883 |
| Polynomial SVC | 0.1234 |

The **Random Forest Classifier** performs best in the first iteration, but the results suggest that aggregating actions into generic categories removes important contextual information.

---

## 4. Context-Aware Behavioral Representation

A second feature-engineering iteration preserves more information from the raw logs.

Regular expressions are used to extract contextual patterns such as:

- screens and software modules,
- screen configurations,
- record categories and other interaction contexts.

Each session is then treated as a document, and `TfidfVectorizer` is applied to create a behavioral signature.

The final representation combines:

- static features,
- action-transition bigrams,
- contextual TF-IDF patterns.

This produces a feature space of approximately **1,943 variables**.

---

## 5. Evaluation Strategy

Because the dataset contains **247 imbalanced classes**, simple accuracy is not sufficient as the main metric.

The primary evaluation metric is therefore the **Macro F1-score**, which computes the F1-score independently for each user and averages the results so that minority and majority classes contribute equally.

Cross-validation is also used to assess model stability and generalization.

---

## Results

With the enriched representation and a `RandomForestClassifier` using 300 trees:

- **Macro F1-score on the 80/20 validation split: 0.878**
- **3-fold cross-validation score: 0.872**
- The project report also records a final test/competition score close to **0.90**

The most important improvement comes from preserving the **context** and **sequence** of user interactions rather than relying only on action counts.

---

## Key Findings

The project highlights three main conclusions:

1. **Contextual TF-IDF patterns are highly discriminative.**  
   The modules, screens, and configurations used by a person provide a strong behavioral signature.

2. **Sequential information matters.**  
   Action bigrams capture recurring interaction workflows that distinguish users.

3. **Static statistics alone are insufficient.**  
   Session duration and action counts are useful, but they do not capture the full behavioral structure.

Overall, the results show that user identity is more strongly associated with **what users interact with and how they navigate the software** than with simple action-frequency statistics.
